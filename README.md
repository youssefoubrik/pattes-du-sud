# Pattes du Sud

Website for a nonprofit care association in Mirleft, Morocco. Built with Next.js, React, TypeScript, Tailwind CSS, and SQLite.

## Requirements

- Node.js 20.9 or newer
- npm
- A writable, persistent disk for the SQLite database in production

## Run locally

```bash
npm ci
cp example.env .env.local
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The app creates `data/site.sqlite` and seeds starter profiles on first use. `.env.local` controls the database path and local site URL; see `example.env` for the available variables.

### Load the sample editor database

To preview the editor with sample profiles, supporters, and settings, stop the dev server and run:

```bash
npm run db:reset-sample
```

This replaces `data/site.sqlite` and saves the previous database to `data/backups/` first. It always targets that local file, even if `DATABASE_PATH` is set. The sample contact, bank, and PayPal details are fictional; the PayPal links do not accept payments. Replace all sample data before using the site publicly. The reset script uses Node’s TypeScript type stripping, available in Node 22.6 and newer.

## Admin editor

Generate a password hash:

```bash
npm run admin:hash
```

Enter a password of at least 16 characters at the hidden prompt. Copy the printed hash into `ADMIN_PASSWORD_HASH` in `.env.local`, then restart the dev server. Sign in at [http://localhost:3000/en/admin](http://localhost:3000/en/admin) with the original password.

Use the editor to manage profiles, supporter names and logos, translated page copy, contact information, the map, and donation settings. These changes are stored in SQLite, not in the source files.

## Database and backups

The SQLite database stores profiles, uploaded media, editor settings and copy, admin sessions, and anonymous page-view and QR-source records. Its default path is `data/site.sqlite`; set `DATABASE_PATH` to change it. Never commit the database or put it on ephemeral serverless storage.

Create a consistent backup with:

```bash
npm run db:backup
```

The backup is written to a `backups/` directory next to the configured database. To restore it, stop the app and replace its database file with the backup. Before restarting, delete any adjacent files for the old database whose names end in `-wal` or `-shm`; these are SQLite working files and must not be carried over to the restored database. Make regular backups and occasionally test that you can restore one.

## Production deployment

Before building and starting the site, configure:

- `NEXT_PUBLIC_SITE_URL` with the public HTTPS origin. It is used for canonical metadata and the sitemap.
- `DATABASE_PATH` with a writable path on persistent storage.
- `ADMIN_PASSWORD_HASH` with a production password hash generated by `npm run admin:hash`.

Then build and start:

```bash
npm ci
npm run build
npm run start
```

After startup, sign in to the editor and enter verified contact, location, and donation details. Check that the one-time and monthly PayPal links work, that bank details are correct, and that sample profiles and supporter entries have been replaced or approved. Keep the production database backed up separately from application deployments.

## Project structure

- `app/` — routes, layouts, API endpoints, sitemap, and robots rules
- `components/` — page sections and shared UI
- `content/` — typed default content and media references
- `lib/database/` — SQLite connection and data access
- `messages/` — English, French, German, and Arabic copy
- `i18n/` and `proxy.ts` — locale routing and language detection
- `docs/` — UX, UI, fundraising, content, and engineering guidance
- `context.txt` — association background and approved source material
